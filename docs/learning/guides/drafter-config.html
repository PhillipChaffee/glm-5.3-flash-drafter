Gated SiLU MLP, width 12,288

SiLU is an activation function. ELSI-C is a separate analysis method for selecting target layers. They are not the same term.

An MLP is the feed-forward network that transforms each token's representation. In the selected gated MLP:

up   = x @ W_up             # 4,096 numbers → 12,288
gate = SiLU(x @ W_gate)     # 4,096 numbers → 12,288
out  = (up * gate) @ W_down # 12,288 numbers → 4,096

SiLU(z) = z * sigmoid(z)

@ is matrix multiplication; * is element-by-element multiplication. The gate continuously modifies the expanded features. SiLU can be negative or greater than one: this is not a binary switch or a percentage restricted to zero through one.

Width 12,288 means 12,288 intermediate features per token. Both branches have that width; their product has the same width. It does not count tokens, streams, or experts. This gated form is also called SwiGLU.

Query heads and KV heads

Each query head computes its own pattern of attention over available positions, producing its own output vector. A KV head provides one set of key and value representations.

These come from learned projections. For our selected 64-head, 64-dimensional layout, the query projection produces 4,096 numbers, then reshapes them into 64 groups of 64. We do not simply chop the original input into fixed semantic categories.

Different queries → different attention weights → different outputs.

Sharing K/V saves their stored representations. With equal dimensions and precision, eight KV heads need one-eighth the K/V-cache storage of 64 KV heads; total model memory does not shrink by that factor.

RoPE theta 10,000

RoPE rotates pairs of query/key coordinates as token position advances. Think of several clock hands moving at different speeds. Relative position changes how the rotated queries and keys match.

Theta sets the spread of those rotation speeds. For default RoPE, frequency for pair i is theta ** (-2*i/d), where d is the number of rotating dimensions.

For an eight-dimensional toy with theta 10,000, the four speeds are:

1, 0.1, 0.01, 0.001 radians per token position

At position 10, their angles are:
10, 1, 0.1, 0.01 radians

Our selected 64-dimensional heads have 32 rotating coordinate pairs. Theta is not a maximum context length or a numerical precision setting. Increasing it changes different frequencies by different factors; it does not guarantee better long-context behavior.

Loss: the score training tries to reduce

A loss is a numerical objective. Training changes the drafter's parameters to reduce it. Our selected baseline combines three signals:

  • Cross-entropy: reward probability assigned to the teacher's most likely next token.
  • Total variation: make the draft's whole token-probability distribution closer to the teacher's.
  • Confidence loss: train the extra head to estimate acceptance probability.
teacher probabilities: [0.8, 0.2]
draft probabilities:   [0.6, 0.4]

TV = 0.5 * (abs(0.8 - 0.6) + abs(0.2 - 0.4)) = 0.2
distribution overlap = 0.8

That overlap is the one-step stochastic acceptance probability at the same prefix, under standard rejection sampling. It is not greedy-match accuracy or whole-block acceptance.

Our selected coefficients are 0.1 × cross-entropy + 0.9 × TV + 1.0 × confidence BCE. They define the initial recipe, not a universal default. Lower training loss alone does not establish faster generation.

Position weighting, not precision weighting

These weights make an error near the start of a proposed block contribute more to training than an error near its end:

proposal:   1     2     3     4     5     6     7     8
weight:   1.00  0.78  0.61  0.47  0.37  0.29  0.22  0.17

weight[j] = exp(-j / 4), with j starting at zero

An early rejection ends the accepted prefix, so later proposals cannot be retained in that round. That motivates giving early correctness extra weight. This particular exponential schedule is a heuristic.

The weight uses the offset inside the draft block, not the absolute conversation position. Our selected reduction divides the weighted sum by the number of valid prediction positions, not by the sum of weights.

Numerical precision is another topic. BF16 and FP32 are floating-point number formats. They affect representation and computation; they are not position weights.
