How four identical streams become different

A stream is a working representation of the same token. GLM carries four of them, learns how to update each, and keeps carrying all four through its layers.

1. Start with four copies

Real GLM has 4,096 numbers in each stream, for each token. We will use just one number per stream so the arithmetic stays visible. These are invented teaching values, not measurements from GLM.

GLM really does start its streams as identical embedding copies. They do not come with predefined jobs such as syntax, reasoning, or memory.

2. Add different amounts of one update

The mHC wrapper combines the streams into one input for attention or a feed-forward operation. In this toy, pre-weights [0.2, 0.4, 0.6, 0.8] make that input 20. Pretend the operation returns an update of 2.

This is how identical copies can diverge. The post gates add different amounts. In the model, the pre/post gates are learned and depend on the incoming representations. They are not required to sum to one.

The existing streams also travel through a bypass mixer. Because all four incoming values are ten, the permitted mixer below leaves this particular bypass unchanged.

3. Constrain the bypass mixer

A matrix is a table of weights. Here a row tells us how to construct one output stream from the four input streams. In GLM, each entry scales a whole 4,096-number stream vector; our toy follows one coordinate.

The first row means output1 = 0.625 × input1 + 0.125 × input2 + 0.125 × input3 + 0.125 × input4.

  • Nonnegative weights: blend inputs without giving any input a negative mixing coefficient. The hidden-state values themselves may still be negative.
  • Every row sums to one: each output is a weighted average rather than an arbitrarily amplified sum.
  • Every column sums to one: each input has total weight one across the outputs. Pure mixing preserves the average across streams.

Both sets of unit sums make a matrix doubly stochastic. The full name Manifold-Constrained Hyper-Connections refers to restricting the residual mixer to this allowed family of matrices. The example is symmetric, but the learned matrix need not be.

The constraint applies only to this bypass mixer. The separately added update can change the mean, as our toy did: ten became an average of 11.25. The pre/post gates follow different rules.

4. Why bother with those rules?

If a bypass simply doubled every stream at every step, ten steps would multiply its values by 2¹⁰ = 1,024. Unrestricted mixing can produce unwanted amplification across depth.

Row sums alone also permit every output to copy only the first stream. For input [4, 0, 0, 0], that produces [4, 4, 4, 4]: the mean changes from one to four, and the other streams are discarded. Column sums prevent that particular concentration.

An exactly doubly stochastic fixed mixer cannot increase the combined Euclidean length of the streams. That is a useful property of the bypass route, not a guarantee about the whole network or its gradients.

It also does not preserve every detail. A matrix with 0.25 in every cell is allowed but replaces every stream with the same average, losing their differences.

How does GLM enforce the rule?

The network produces mixing scores, turns them into positive weights, and repeatedly normalizes rows and columns. Fixing column totals can disturb row totals, which is why it repeats. This procedure is called Sinkhorn normalization.

GLM uses 20 iterations and small numerical epsilon terms, so the numerical condition is approximate. Its matrix changes with the incoming state. Our table is an already-valid illustration.

5. Run the tiny example

This uses only Python. The line computing update stands in for the whole normalized attention/feed-forward computation; this is not a miniature trained GLM.

streams = [10.0] * 4
pre = [0.2, 0.4, 0.6, 0.8]
post = [0.25, 0.5, 0.75, 1.0]
C = [[0.625 if i == j else 0.125 for j in range(4)]
     for i in range(4)]

combined = sum(a * x for a, x in zip(pre, streams))
update = 0.1 * combined  # Invented teaching operation.
mixed = [sum(w * x for w, x in zip(row, streams)) for row in C]
result = [old + gate * update for old, gate in zip(mixed, post)]

assert all(sum(row) == 1.0 for row in C)
assert all(sum(column) == 1.0 for column in zip(*C))
assert result == [10.5, 11.0, 11.5, 12.0]
print(result)

Executed successfully on 2026-10-24. The independent checks also covered subsequent mean-preserving mixing and example iterative normalization.

Recall check: without the added update, would four identical copies become different?

No. Unit-sum rows blend four identical values back into that same value. The different post-gated update amounts make them diverge here.

Recall check: does the constraint forbid negative stream values?

No. It constrains the mixing weights. A blend of negative hidden-state values can still be negative.

6. Does DeepSeek combine its streams?

Yes for the conditioning features, while its native drafter also has its own four internal streams. Those are two separate facts.

  1. The native DeepSeek target carries four streams through its blocks.
  2. At each of three selected blocks, it averages those four streams into one context vector. The target keeps its full continuing state.
  3. Those three vectors condition the native drafter. Separately, the drafter expands its anchor/mask embeddings into four new draft streams.
  4. Its three mHC draft layers update those streams. A learned final reduction produces a single vector for the output path.

The four draft streams are not the four raw target streams handed across unchanged. DeepSeek's public Qwen/Gemma reference drafters use ordinary single-stream residuals instead.

For our approved initial GLM drafter, we average the target streams at each selected layer and feed the resulting vectors to a single-stream dense draft model. GLM itself ends with an unweighted stream average followed by normalization; native DeepSeek uses a learned final stream reduction.

Primary reading: GLM's mHC implementation and diagram. The mHC paper explains the constraint; native DeepSeek code shows averaging and fresh draft-stream expansion.
